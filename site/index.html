Prove the bug, don't just guess it.

A user says "I couldn't save, I tried three times." reprobe gathers what production saw, read-only. Your coding agent finds the cause, with every claim citing evidence, and writes a test that fails on the code you deployed.

$npx reprobe init

Free and MIT licensed. No server, no account, no hosted model. It runs on your machine with your agent.

How it works

The CLI does the parts that must be exact. Your agent does the thinking.

Like npx t3 triage, reprobe packages the facts and a playbook, then starts Claude Code or Codex in your repo. Gathering, access control, redaction, citation checks and replays at old commits stay deterministic.

01 · gather

Evidence, read-only

Database rows, agent traces, server logs and Sentry issues for the user and the time window. Each item gets a stable id. Missing or expired sources are listed, never guessed around.

02 · investigate

Your agent, cited

The agent reads the case, the code at the deployed commit, and digs further through reprobe's read-only tools. Its diagnosis drops any claim that cites no evidence.

03 · prove

A replay that fails today

The agent writes the smallest test of the broken invariant. reprobe runs it in a detached worktree at each commit: FAIL on the deployed code, PASS on the fix.

$ npx reprobe "users on build 155 can't see their groups"
reprobe: connecting to Postgres (read-only)
reprobe: reading logs
~/.reprobe/cases/api/2026-09-08-7d2e91/report.md
top: [medium] Server lists 10 live groups the user cannot see: likely the app's local cache
Starting Claude Code in ~/code/app.

… the agent writes replay.json, then:
$ reprobe verify <case> 4f1c2a9e0b b72e05d1c3
4f1c2a9e0b FAIL Actual: Set:[]  Which: does not contain 'grp_8f3…'
b72e05d1c3 PASS  replay passed
Proof, not plausibility

One test, run across your history.

An explanation can sound right and be wrong. A test that fails on the commit users ran, and passes on the fix, can't. Here is a real incident: the first fix shipped and the bug stayed.

The replay still failed at the first fix, which is exactly why users on build 156 kept seeing the bug. A run that crashes before its assertion is marked BROKEN, so a crash can never pass for a reproduced bug.

Safety

Read-only guardrails, not a sandbox.

The built-in database path checks every query and transaction. Configured commands, packs, agents and replay tests still run with your machine's permissions.

postgreslangfuselangsmithsentryrailwayany log CLIlog files
  • Database reads have three guardrails. A SELECT-only guard, a read-only session, and BEGIN READ ONLY … ROLLBACK. Use least-privilege database grants too.
  • Replays are checkout-isolated, not machine-isolated. They use detached worktrees and launch without a shell, but test code can still access your environment, files, databases and network.
  • Configured code is trusted code. Secret-provider and log-source commands, pack hooks, and agents run with your local permissions. Headless tool limits are not an OS sandbox; even an allowed git command can write outside the worktree.
  • Redacted by default. Phones, emails, tokens and keys are removed before a case is written. Pattern-based redaction can miss opaque secrets; cases live outside your repo.
  • The built-in flow does not post evidence. It does not send writes to Sentry, GitHub or users. An agent or configured command remains trusted code, and should treat evidence as data, not instructions.
Questions

Before you try it

What does it cost?

Nothing. reprobe is MIT licensed and has no server. The investigation runs on the Claude Code or Codex you already use, so the only cost is your own agent's usage.

Does my data leave my machine?

Evidence goes to the agent you choose, the same as when you paste logs into it today. reprobe itself sends nothing anywhere, and cases are written to ~/.reprobe/cases.

What if I don't use Postgres or Railway?

Every source is optional. Logs can come from any CLI that prints lines (fly, vercel, kubectl, docker) or from files. Without a database, reprobe still works from traces, logs and Sentry.

What is a pack?

One TypeScript file that teaches reprobe your product: how to find the user a complaint is about, which rows matter, your known failure signatures, and how to build an old commit. Every hook is optional.

Which agents work?

Claude Code and Codex start automatically. With neither installed, reprobe prints one line to paste into any coding agent.
